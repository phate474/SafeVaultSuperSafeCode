# SafeVault

SafeVault is a .NET 10 minimal API example for secure user registration, login, and role-based access to user data. It uses SQLite for persistence and JWT bearer tokens for API authentication.

## Security features

- **Input validation:** Registration trims and sanitizes usernames, validates email addresses, and requires passwords of 12–128 characters. Passwords are not trimmed or modified.
- **SQL injection protection:** All user-provided database values are passed as SQLite parameters. Usernames are unique without regard to case.
- **XSS protection:** API JSON uses `JavaScriptEncoder.Default`; usernames are also restricted to letters, numbers, spaces, `.`, `_`, and `-`.
- **Password storage:** New passwords are hashed with BCrypt.Net-Next using enhanced SHA-384 preprocessing and work factor 11. Random salts are generated by the library. Enhanced hashing avoids bcrypt's 72-byte input limit.
- **Legacy password migration:** Existing ASP.NET Identity password hashes are verified during login and upgraded to BCrypt after successful authentication. Accounts with no stored password hash cannot log in until their credentials are reset.
- **Authentication:** Successful login issues a 15-minute JWT. The API validates the signature, issuer, audience, and expiration. Invalid credentials return the same unauthorized response.
- **Authorization:** New registrations receive the `User` role. The optional bootstrap account receives the `Admin` role. Users may read their own profile; Admins may also read other profiles and list users. Users cannot select their own role.
- **Database migration:** Startup adds the password-hash and role columns to an older `Users` table and creates a case-insensitive unique username index.
- **Local secret hygiene:** `.gitignore` excludes local SQLite databases, database sidecars, and `.env` files. Keep real secrets in environment variables or a secret manager, never in source control.

## API

| Method | Route | Access | Description |
|---|---|---|---|
| `POST` | `/submit` | Anonymous | Registers a user from form-encoded `username`, `email`, and `password`; returns `201 Created` or validation errors. |
| `POST` | `/auth/login` | Anonymous | Accepts JSON `username` and `password`; returns a bearer token or `401 Unauthorized`. |
| `GET` | `/users/{userId}` | Authenticated owner or Admin | Returns a user's profile; other authenticated users receive `403 Forbidden`. |
| `GET` | `/admin/users` | Admin role | Lists user profiles without password hashes. |

Development OpenAPI is available at `/openapi/v1.json`. Example HTTP requests are in [SecurityRealWorldExample.http](./SecurityRealWorldExample.http).

## Configuration

`appsettings.json` contains the SQLite connection string and non-secret JWT issuer/audience values. The application requires:

- `Authentication__Jwt__SigningKey`: a secret of at least 32 UTF-8 bytes.
- To create the initial Admin account, set all three:
  - `SafeVault__BootstrapAdmin__Username`
  - `SafeVault__BootstrapAdmin__Email`
  - `SafeVault__BootstrapAdmin__Password` (12–128 characters)

The bootstrap settings are optional as a group. If omitted, registration still works, but no Admin account is provisioned. Bootstrap credentials are used to create an Admin only when that username does not already exist; an existing non-Admin account with that username causes startup to fail rather than being silently promoted.

Do not use the test signing key or test account credentials outside the test environment.

## Build and test

From the project directory:

```powershell
dotnet restore
dotnet test .\Tests\SecurityRealWorldExample.Tests.csproj
dotnet build .\SecurityRealWorldExample.csproj
```

The NUnit integration suite validates:

- SQL injection payloads are treated as data by the store and sanitized at the registration endpoint.
- Script markup submitted in a username is sanitized and not returned as executable HTML.
- Invalid email input is rejected.
- Passwords are stored as salted BCrypt hashes; identical passwords produce different hashes.
- Correct credentials issue a token; incorrect credentials are rejected.
- Passwords longer than bcrypt's native 72-byte limit are fully verified.
- Legacy ASP.NET Identity hashes are upgraded after successful login.
- Registration assigns the `User` role, bootstrap assigns `Admin`, and anonymous/regular/Admin access is checked for protected routes.

The test project uses an isolated temporary SQLite database.
